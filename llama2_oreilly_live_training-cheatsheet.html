Reusable Helper
import ollama

def chat(prompt, model="gemma4",
         system=None):
    messages = []
    if system:
        messages.append({
            "role": "system",
            "content": system
        })
    messages.append({
        "role": "user",
        "content": prompt
    })
    resp = ollama.chat(
        model=model,
        messages=messages
    )
    return resp['message']['content']

# Usage
answer = chat("What is LoRA?")
print(answer)
Module 2 — Introduction to RAG

Load documents from files / URLs
2
Chunk
Split into overlapping segments
3
Embed
Convert chunks to dense vectors
4
Index
Store in vector database
5
Retrieve
Find similar chunks (cosine sim)
6
Generate
LLM answers using retrieved context
Embeddings
Dense vector representations capturing semantic meaning. Similar text → similar vectors.
Chunking
Split docs into overlapping segments. Typical: 512–1024 tokens, 20-token overlap.
Chunk Size Trade-off
Smaller → precise retrieval, less context. Larger → more context, noisier results.
Module 3 — Local RAG with Gemma 4 + LlamaIndex
Build Index & Query
from llama_index.llms.ollama import Ollama
from llama_index.embeddings.huggingface \
    import HuggingFaceEmbedding
from llama_index.core import (
    VectorStoreIndex,
    SimpleDirectoryReader, Settings
)

Settings.llm = Ollama(
    model="gemma4",
    request_timeout=120.0
)
Settings.embed_model = HuggingFaceEmbedding(
    model_name="BAAI/bge-small-en-v1.5"
)
docs = SimpleDirectoryReader("data/").load_data()
index = VectorStoreIndex.from_documents(docs)
engine = index.as_query_engine(
    similarity_top_k=3
)
response = engine.query("What is LoRA?")

Module 4 — Tool Calling with Ollama
Define & Register Tools
import ollama

def get_weather(city: str) -> str:
    return f"Weather in {city}: 22°C sunny"

tools = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "Get weather for a city",
        "parameters": {
            "type": "object",
            "properties": {
                "city": {"type": "string"}
            },
            "required": ["city"]
        }
    }
}]

response = ollama.chat(
    model="gemma4",
    messages=[{
        "role": "user",
        "content": "Weather in Paris?"
    }],
    tools=tools
)
Execute Tool Calls
tools_map = {"get_weather": get_weather}

if response.message.tool_calls:
    for tc in response.message.tool_calls:
        fn = tools_map[tc.function.name]
        result = fn(**tc.function.arguments)

        # Feed result back to model
        messages = [
            response.message,
            {
                "role": "tool",
                "content": str(result),
                "name": tc.function.name
            }
        ]
        final = ollama.chat(
            model="gemma4",
            messages=messages
        )
        print(final.message.content)
Module 5 — Local Agents: Structured Outputs → Agent Loop
Structured Outputs (Pydantic)
from pydantic import BaseModel
import ollama

class Task(BaseModel):
    title: str
    priority: str   # high/medium/low
    estimated_hours: int

response = ollama.chat(
    model="gemma4",
    messages=[{
        "role": "user",
        "content": "Create a task to build login page"
    }],
    format=Task.model_json_schema()
)
task = Task.model_validate_json(
    response.message.content
)
print(task.title, task.priority)
Agent Concepts Summary
# Agent Loop pattern:
# User → LLM decides tool → Execute tool
# → Feed result back → LLM final response

# Concept        Ollama Feature
# -----------   --------------------------
# Structured    format=Schema.model_json_schema()
# Outputs
#
# Tool Calling  tools=[{type, function...}]
#               (LLM decides which to call)
#
# Agent Loop    Combine both:
#               1. Send messages + tools
#               2. Execute tool_calls
#               3. Append tool results
#               4. Re-call chat() until
#                  no tool_calls remain
Module 6 — Agentic RAG: ReAct Pattern
Simple ReAct Agent (Reason → Act → Observe loop)
import ollama

class SimpleReActAgent:
    def __init__(self, model="gemma4", tools=None, tools_map=None, max_turns=10):
        self.model, self.tools = model, tools or []
        self.tools_map, self.max_turns = tools_map or {}, max_turns
        self.messages = []

    def run(self, user_input: str) -> str:
        self.messages.append({"role": "user", "content": user_input})
        for turn in range(self.max_turns):
            response = ollama.chat(model=self.model, messages=self.messages, tools=self.tools)
            if not response.message.tool_calls:
                return response.message.content           # No tool call = final answer
            self.messages.append(response.message)
            for tc in response.message.tool_calls:        # Execute each tool
                result = self.tools_map[tc.function.name](**tc.function.arguments)
                self.messages.append({"role": "tool", "content": str(result), "name": tc.function.name})
        return "Max turns reached."

# Extend by: adding tools, adjusting max_turns, custom system prompt, adding memory
ReAct Loop: Reason → Act → Observe (repeat until done)
  • Turn 1: Agent receives query, calls tool (e.g. find_pdfs) to discover resources
  • Turn N: Agent receives tool results, may call more tools or synthesise final answer
  • Done: When LLM returns a response with no tool_calls
Module 7 — Useful Local Agents: When Local vs Cloud
Local Agent ✓ Use When…
  • Privacy matters — data must stay on device
  • Cost control — no per-token billing
  • Single-tool chains with deterministic output
  • Private document analysis
  • Offline / air-gapped environments
  • Running Hermes Agent (local TUI + memory)
Cloud Agent ✓ Use When…
  • Long-context synthesis (>64K tokens)
  • Multi-hop reasoning chains (complex logic)
  • Code edits beyond ~200 LOC
  • Ambiguous planning needing world knowledge
  • Tasks needing latest internet data
  • High-quality generation is critical
Module 8 — Fine-Tuning (LoRA, QLoRA, PEFT)
Methods
MethodDescription
SFTSupervised Fine-Tuning: instruction→response pairs
RLHFReinforcement Learning from Human Feedback
PEFTUpdate only a small subset of parameters
LoRATrain small adapter matrices A,B (10,000× fewer params)
QLoRA4-bit quantized base + LoRA adapters in higher precision
When to Fine-Tune
  • Cost: Replace expensive GPT-4 with cheaper fine-tuned model
  • Latency: Smaller model = faster responses
  • Consistency: Model reliably follows specific format/style

Start with prompting. Fine-tune only when product shape is finalized and use case is clear.

Q4 Key Insight

INT4 (Q4) quantization lets you fit models 2× larger than your VRAM on the same hardware.
Example: Gemma4 26B (MoE, Q4) runs on 8GB VRAM — it activates only 3.8B params per token.

Course Key Takeaways
  • Ollama — One command to run any open-weight model locally (ollama pull + ollama.chat())
  • RAG — Load → Chunk → Embed → Index → Retrieve → Generate: give LLMs access to your own documents
  • Tool Calling — Pass tools=[...] to Ollama; LLM decides which function to call and with what args
  • Agents — Structured outputs (Pydantic) + tool calling + a loop = a capable local agent
  • ReAct — Reason → Act → Observe loop; keep looping until no tool_calls in response
  • Local vs Cloud — Local wins on privacy and cost; cloud wins on long context, complex reasoning, and latest data
  • Fine-Tuning — Use QLoRA (4-bit base + LoRA adapters) for consumer hardware; only fine-tune when task is well-defined
  • Quantization — INT4 (Q4) fits 8× more model into same VRAM at minimal quality cost
  • Gemma 4 — Course default: multimodal, Apache 2.0, #3 Chatbot Arena, all hardware tiers covered
